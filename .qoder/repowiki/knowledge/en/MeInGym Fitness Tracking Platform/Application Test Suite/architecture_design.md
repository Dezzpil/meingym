Tests mirror the source layout under src/tests/ with three top-level groups: `core/` validates pure business logic (progression strategies, difficulty, periods, scores) without HTTP or DB context; `mobile-auth/` covers token lifecycle and HMAC exchange; `tools/` exercises utility functions. Each test file imports production code via `@/*` path aliases and uses `node:test` with nested `context.test` blocks for hierarchical grouping. Assertions come from Chai (`assert` style in core/tools, `expect` BDD style in mobile-auth). Tests are self-contained and dependency-light, relying only on Prisma types for enums like `ActionRig` and `Purpose`, never instantiating Prisma Client or making network calls.
