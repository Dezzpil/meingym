Tests mirror the source layout under src/tests/ with four top-level groups: `core/` validates pure business logic (progression strategies including duration-based ones, difficulty, periods, scores, stats, records) without HTTP context; `mobile/` covers the mobile API services and route handlers (trainings, syncTrainings, scores, records); `mobile-auth/` covers token lifecycle, HMAC and registration; `tools/` exercises utility functions. Each test file imports production code via `@/*` path aliases and uses `node:test` with nested `context.test` blocks for hierarchical grouping. Assertions come from Chai (`assert` style in core/tools, `expect` BDD style in mobile and mobile-auth). Tests are self-contained and dependency-light: no test connects to PostgreSQL or Redis — Prisma methods are monkey-patched in place (the original function is saved and restored in `after`), and `mobile/syncTrainings.test.ts` registers `mock.module` replacements for `@/core/exercises` and `@/jobs` before importing the module under test, which is why `npm run test:mobile` and `npm run test:mobile-auth` run with `--experimental-test-module-mocks`.
