Tests run via the project's node:test runner with tsx — no separate test framework configuration needed. One script per group: `npm run test:core`, `npm run test:mobile`, `npm run test:mobile-auth`, `npm run test:tools`; there is no combined `npm test` script. `test:mobile` and `test:mobile-auth` add `--experimental-test-module-mocks` because they replace `@/jobs` and `@/core` modules. Single progression scenarios have their own scripts (`test:core:progression`, `test:core:progression1`, `test:core:progression2`). Mobile auth tests require `MOBILE_JWT_SECRET` and `MOBILE_JWT_EXPIRES_IN_SECONDS` environment variables set before import (as shown in jwt.test.ts). No database or Redis connection is required since Prisma and queue calls are stubbed inside the tests.
