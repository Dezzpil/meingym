Each file is an independent CLI entry point executed via `npx tsx`, with no shared runtime or orchestration layer. Scripts follow a uniform shape: load `.env.local` via dotenv, import the singleton Prisma client from `@/tools/db`, perform read/write operations against the Prisma schema, and exit with code 0 on success or 1 on fatal error. Data mutations reuse application logic where available — `update-actions.ts` and `update-training-exercises.ts` call `handleUpdate` from `@/app/actions/actions`, while statistics recalculation delegates to `calculateStats` and `createScore` from `@/core/stats` and `@/core/scores`. The mobile-auth-test script is an outlier: it does not touch the database but instead constructs HMAC signatures and invokes the live `/api/mobile/v1/*` endpoints via `curl` through `child_process.execSync`. Dependency direction is one-way: scripts depend on `@/tools/db`, `@/app/actions/actions`, and `@/core/*` modules, never the reverse.
