The module is a dependency-light core layer that only depends on Prisma Client (via `@/tools/db` singleton) and Chai assertions. It is organized into flat files for top-level concerns (`approaches.ts`, `exercises.ts`, `scores.ts`, `stats.ts`, `difficulty.ts`, `periods.ts`, `trainingMuscles.ts`) plus three sub-packages with pluggable interfaces:
- `difficulty/` defines the `TrainingDifficultyBoostStrategy` interface (`boostStrategy.ts`) with an `ExtraApproachesBoostStrategy` implementation (`extraApproachesBoost.ts`) and server-action entry points (`recalculate.ts`) to persist recalculated difficulty scores.
- `trainingTime/` defines an abstract `TrainingTimeScorer` base class (`scorer.ts`) with two implementations: `TrainingTimeAvgScorer` (rule-based minutes-per-approach) and `TrainingTimeMLScorer` (NDJSON request to a local ML service on port 5001).
- `progression/strategy/simple.ts` implements `ProgressionStrategySimple`, a configurable class producing next-session sets based on executed sets and per-purpose rules.

Dependency direction is inward: higher-level modules call these functions; within the module, `exercises.ts` composes `approaches.ts` which delegates to `stats.ts` for aggregate computation. All database mutations accept a `PrismaTransactionClient` parameter so they can run inside transactions or use the global `prisma` singleton directly (as in `periods.ts`). Types are centralized in `types.ts` (`SetData`, `SetDataExecuted`, `SetsStats`, `CurrentPurpose`).
