The module is a dependency-light core layer that only depends on Prisma Client (via `@/tools/db` singleton) and Chai assertions. It is organized into flat files for top-level concerns (`approaches.ts`, `exercises.ts`, `scores.ts`, `stats.ts`, `difficulty.ts`, `periods.ts`, `trainingMuscles.ts`, `trainingProcessing.ts`) plus four sub-packages with pluggable interfaces:
- `difficulty/` defines the `TrainingDifficultyBoostStrategy` interface (`boostStrategy.ts`) with an `ExtraApproachesBoostStrategy` implementation (`extraApproachesBoost.ts`) and server-action entry points (`recalculate.ts`) to persist recalculated difficulty scores.
- `trainingTime/` defines an abstract `TrainingTimeScorer` base class (`scorer.ts`) with two implementations: `TrainingTimeAvgScorer` (rule-based minutes-per-approach norms from `estimate.ts`: STRENGTH 5, MASS 3.5, LOSS 2) and `TrainingTimeMLScorer` (NDJSON request to a local ML service on `TIME_SCORER_PORT`, default 5001). Only `TrainingTimeAvgScorer` is used — every caller in `src/app/**/actions.ts` instantiates it; the ML scorer and its dataset script (`src/scripts/collect-exercise-time.ts`) are an abandoned experiment kept in the tree.
- `records/` is the personal-record engine: `detect.ts` finds new `PersonalRecord`s for a completed training (`detectPersonalRecordsForTraining`), `engine.ts` builds candidates, `valuation.ts` filters recordable executions and computes max-weight / volume / duration values, `evaluate.ts` decides whether a candidate beats the previous record, and `recalculate.ts` rebuilds all records for a user (`recalculatePersonalRecordsForUser`, mirrored by the CLI script). `types.ts` and `index.ts` carry the shared shapes and the public barrel.
- `progression/strategy/simple.ts` implements `ProgressionStrategySimple`, a configurable class producing next-session sets based on executed sets and per-purpose rules; duration-based exercises are handled inside the same class rather than in a separate strategy.
- `trainingProcessing.ts` exposes `processCompletedTrainingCore(trainingId, userId)`, the single entry point that runs records, muscle and statistics recomputation and then enqueues score calculation; the web pages and the `trainings` Bull worker both call it.

Dependency direction is inward: higher-level modules call these functions; within the module, `exercises.ts` composes `approaches.ts` which delegates to `stats.ts` for aggregate computation. All database mutations accept a `PrismaTransactionClient` parameter so they can run inside transactions or use the global `prisma` singleton directly (as in `periods.ts`). Types are centralized in `types.ts` (`SetData`, `SetDataExecuted`, `SetsStats`, `CurrentPurpose`).
