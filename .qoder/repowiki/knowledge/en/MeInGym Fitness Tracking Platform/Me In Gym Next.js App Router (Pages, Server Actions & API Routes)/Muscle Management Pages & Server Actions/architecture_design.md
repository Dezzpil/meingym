Built as a Next.js App Router route group under `src/app/muscles/` with three top-level routes: the list page (`page.tsx`) queries all muscles via Prisma with related AgonyInActions/SynergyInActions and supports URL-based sorting; the create page (`create/page.tsx`) is admin-only and reuses the shared `MuscleForm`; and the dynamic `[id]` detail page composes multiple client components (MuscleDescForm, MuscleImagesSection, MuscleInActions) around a single muscle record fetched with full includes. Mutations go through `actions.ts` using Next.js Server Actions marked with `'use server'`, which call Prisma directly and use `revalidatePath` or `redirect` for navigation. Image management is split from mutations — it uses a separate REST-style `/api/muscle-images` endpoint called from client components via `fetch`, keeping image upload/delete logic out of server actions. Shared form logic lives in `components/MuscleForm.tsx`, while per-muscle sub-components live under `[id]/components/`. Zod schemas in `create/types.ts` define the form shape shared between client and server.
