Follows Next.js App Router conventions with a flat route structure: `page.tsx` lists equipment rows fetched server-side via Prisma; `create/page.tsx` and `[id]/page.tsx` render the shared `components/EquipmentForm.tsx` client component. Mutations are implemented as Server Actions in `actions.ts` (`handleEquipmentCreate`, `handleEquipmentUpdate`, `handleEquipmentDelete`) which enforce ownership through `assertOwner` and use `prisma.$transaction` for atomic writes. Schema validation is centralized in `types.ts` using Zod schemas (`EquipmentFormFields`, `EquipmentRigField`) that mirror Prisma enums `ActionRequire` and `ActionRig`, and also export label maps (`ACTION_REQUIRE_LABELS`, `ACTION_RIG_LABELS`) used by both server pages and the client form. Dependency direction is strictly one-way: client components call server actions, server actions call `@/tools/db` and `@/tools/auth`, and no cross-imports exist between routes.
