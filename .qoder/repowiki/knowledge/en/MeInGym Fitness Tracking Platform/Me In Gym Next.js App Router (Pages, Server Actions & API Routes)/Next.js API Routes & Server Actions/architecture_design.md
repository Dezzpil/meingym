Endpoints are organized as Next.js App Router route files under `src/app/api/`, with one handler per file exporting async functions named after HTTP methods (GET/POST/PATCH/DELETE). Two routing patterns coexist: traditional API routes under `/api/*` for REST resources (images, muscle-images, jobs, exercises/similar) and a versioned mobile API under `/api/mobile/v1/*` that uses Bearer JWT tokens via `@/mobile/tools/jwt`. Authentication is handled through NextAuth at `/api/auth/[...nextauth]/route.ts` using the shared `authOptions` from `@/tools/auth`. All database access goes through the Prisma singleton exported from `@/tools/db`. Business logic is delegated to domain modules (`@/mobile/exchange`, `@/mobile/tools/user`, `@/jobs`) rather than being implemented inline. The `/api/trainings/exercise/execution/{complete|uncomplete}` routes implement the training execution feedback model with typed DTOs matching Prisma enum types (ExecutionRating, ExecutionTechnique, etc.). Queue monitoring at `/api/jobs` reads status from Bull queues (`scoresQueue`, `periodsQueue`) exposed via `@/jobs`.
