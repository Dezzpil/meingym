The app module is organized as a set of co-located feature directories under src/app/, each following the same pattern: a page.tsx for rendering, an actions.ts file for server-side mutations, and a components/ folder for UI pieces. All features share a common root layout (layout.tsx) that injects AuthProvider, Layout, and BootstrapJS globally. Mutations go through 'use server' functions in per-feature actions.ts files which call the shared prisma singleton from @/tools/db and use revalidatePath/redirect for cache invalidation and navigation. Data fetching and specialized endpoints live under src/app/api/ as Next.js Route Handlers, exposing REST endpoints for authentication, exercise execution, image uploads, job monitoring, and mobile clients. Feature pages import core business logic (e.g., calcActionBase from @/core/exercises) and Prisma types (@prisma/client), keeping the app layer thin and focused on routing, form handling, and presentation.
