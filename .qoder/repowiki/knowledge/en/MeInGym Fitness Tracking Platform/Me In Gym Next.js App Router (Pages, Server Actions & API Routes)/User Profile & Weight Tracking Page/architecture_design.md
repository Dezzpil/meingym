Follows Next.js App Router conventions: `page.tsx` is the server component entry point that fetches session via `getServerSession`, reads `UserInfo` and current training period through Prisma, and composes client components (`ProfileForm`, `WeightsChart`) plus shared UI from other app routes (`TrainingPeriodManager`, `SimpleProgressionOptsForm`). Mutations are isolated in `actions.ts` as a `'use server'` module using the Prisma singleton from `@/tools/db`. Validation schema lives in `types.ts` built on Zod with Prisma enums (`Sex`, `Purpose`, `TrainingProgression`). The `components/` directory holds pure client components marked with `'use client'`, keeping data fetching on the server side. Dependency direction is one-way: page → server action → Prisma; client components only import types and call server actions.
