Single Prisma schema (`schema.prisma`) targeting PostgreSQL via `DATABASE_PRISMA_URL`, generating a type-safe Prisma Client. The domain is organized around core entities: `User` (with NextAuth `Account`/`Session`/`VerificationToken`), `Action` (exercises) linked to `Muscle`/`MuscleGroup` through four relationship tables (`ActionsOnMusclesAgony/Synergy/Stabilizer/Antagonist`), `Training` → `TrainingExercise` → `ApproachesGroup` → `Approach` → `TrainingExerciseExecution` forming the execution chain, plus scoring (`TrainingExerciseScore`), periods (`TrainingPeriod` + `ProgressionStrategySimpleOpts`), equipment (`Equipment`/`EquipmentRequire`/`EquipmentRig`), and media (`ExerciseImage`/`MuscleImage`). Each entity follows a uniform pattern with `createdAt`/`updatedAt` timestamps, cascade deletes on relations, and explicit indexes (e.g., GIN trigram index on `Action.search`). Migrations live under `migrations/<timestamp>_<name>/migration.sql`, one per database change, managed by Prisma Migrate with a `migration_lock.toml` lockfile.
