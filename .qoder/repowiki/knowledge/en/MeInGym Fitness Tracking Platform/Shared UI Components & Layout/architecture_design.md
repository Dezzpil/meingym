All components are React Server Components marked with `"use client"` where they need interactivity (state, effects, hooks). The module is organized into flat utility components at the root (`Layout`, `AuthProvider`, `Loader`, `NumberDiffViz`, `NameOfTheDay`, `PurposeText`, `SetsStats`, `TrainingsPicker`) and two small feature sub-packages: `approaches/` (form-driven approach-group editor with `Managment.tsx` + `ManagmentElement.tsx`) and `recharts/` (a single `CustomizedAxisTick` axis renderer). Components consume data from `@prisma/client` types directly and call Server Actions via `@/app/*/actions` imports — there is no API layer between components and mutations. Styling relies on Bootstrap CSS classes and `classnames` for conditional styling; third-party JS (Bootstrap) is loaded imperatively through a dedicated `BootstrapJS` component that requires it in a `useEffect`. Dependency direction is one-way: components depend on `@/core/*` types and `@/tools/*` utilities, never the reverse.
